# Contributing

Thank you for helping improve Votrixain.

## Before opening a pull request

1. Describe the problem and the behavior you expect.
2. Keep URL-cleaning rules conservative. Do not remove functional query parameters unless there is a clear reason and a test.
3. Add or update tests for every change to URL parsing, redirect rules, permissions, or popup behavior.
4. Run `npm test` and confirm all tests pass.
5. Do not add analytics, remote code, link collection, or external processing services without first discussing the privacy implications in an issue.

## Pull requests

Keep changes focused and explain any permission or privacy impact in the pull request description. Include steps to reproduce user-visible changes. Do not include API keys, access tokens, browser profiles, or private URLs in commits.
